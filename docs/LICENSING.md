# Licensing and commercial-use audit

**Reviewed:** 1 November 2026
**Product intent:** paid, closed-source distribution
**Question:** may each dependency, reference and asset be redistributed inside a paid product?

This file is the source of truth for the credits page and the generated notices.
If a future integration changes an answer here, it ships only after the table is
updated.

---

## 1. Policy

1. Runtime code and assets must permit **commercial use** and, where relevant,
   redistribution inside a closed-source product.
2. Copyleft licenses that would force source disclosure of the product
   (GPL, AGPL, SSPL) are not acceptable as bundled code. They are not bundled.
3. Non-commercial (NC) assets are not bundled. This is why the Minecraft Wiki is
   used only as a factual reference: its prose is CC BY-NC-SA 3.0, and none of
   it is reproduced.
4. Attribution is not optional. MIT/ISC/OFL notices are preserved in
   [`public/THIRD_PARTY_NOTICES.txt`](../public/THIRD_PARTY_NOTICES.txt), the
   font OFL files live in `public/fonts/`, and the credits page names every
   project.
5. Linter semantics may be inspired by existing tools. That is credited. Their
   code is not copied unless the license permits it and the notice is added.

## 2. Linting tools

cmdlib ships its own linter, written in TypeScript against the same parser the
runtime uses. Two established projects informed the rule vocabulary and the
expectations of datapack authors.

| Project | License | Paid use | Bundled | How used |
| --- | --- | --- | --- | --- |
| [Spyglass](https://github.com/SpyglassMC/Spyglass) | MIT | Yes, with notice | No | Reference implementation for mcfunction diagnostics, selector semantics and command data. Diagnostics use LSP-compatible ranges/codes so output can move between tools. |
| [mclint](https://www.npmjs.com/package/mclint) | ISC | Yes, with notice | No | Cross-check for lint rule vocabulary. No mclint code is imported. |
| [Minecraft Wiki](https://minecraft.wiki/) | CC BY-NC-SA 3.0 (text) | Facts only | No | Command syntax, NBT fields, version history and pack formats. No wiki prose, images or templates are copied. |

**Why not bundle Spyglass?** It is MIT and *could* be bundled with attribution.
It is not, for two reasons: it is an LSP implementation built around Node
services rather than a browser runtime, and the product needs diagnostics that
share the exact grammar and world state of the simulator. Being inspired by it
is credited; copying it is not necessary.

**LSP interoperability.** The Problems panel exports an array of
`{ range, severity, code, source, message }` objects. That is the shape a
Language Server Protocol client expects for diagnostics. It is an export
format, not an embedded server.

## 6. Re-verification checklist

Before a release:

- [ ] `npm run notices` run and `public/THIRD_PARTY_NOTICES.txt` committed.
- [ ] `package.json` dependency diff reviewed for new licenses.
- [ ] No new asset that lacks a license entry above.
- [ ] Any new linter integration has a row in section 2 and a notice if code is
      copied.
- [ ] `LICENSE` and the credits page still describe the correct product
      licensing status.
