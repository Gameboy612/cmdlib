01 · The loop

You already know
this workflow.

Launch the game to test a datapack. Wait for the world. Type a command. Watch nothing happen. Reload. Guess. Repeat.

↳

cmdlib started with a smaller question: what if the edit and the answer lived in the same tab?

    Cold start

    wait

    The launcher, the assets, the world. Every idea pays this tax first.

  2. 02

    World load

    wait

    Chunks stream in while you remember where your test rig lives.

  3. 03

    /reload

    context

    The closest thing to a fast loop the game has. Still a full stop.

  4. 04

    The typo

    guess

    One wrong NBT path. No stack trace, just silence and a guess.

  5. 05

    Relaunch

    wait

    Because sometimes /reload is not enough, and you already closed it.

01

Drag anything anywhere

Explorer, editor, preview, console, scoreboards, storage. Split a tab, float a panel, close what you do not need. Your layout is remembered.

02

One command palette

Cmd/Ctrl + K reaches every action: run the load tag, open the demo, switch versions, export the pack, jump to a problem.

03

The preview is the state

There is no fake screenshot. The viewport projects the actual world model, so changing an entity's Pos in NBT moves the entity.

04

Keyboard first

F5 reloads the pack, Ctrl/Cmd + Enter runs the active function, Ctrl/Cmd + S saves locally. No mouse required.

04 · Versions

Built for 26.3.
Not trapped in it.

A version is a profile, not a branch: folder names, pack metadata, macro support and text component syntax all live in one table. The editor migrates the pack when you switch, then re-lints every command against the target version.

When 26.4 lands, cmdlib adds a row. It does not fork the product.

05 · Correctness

Correct
before you
launch.

The linter is not a regex. It parses every line with the same grammar the runtime executes, checks objectives and functions across the whole pack, and understands which commands exist in which version.

01

Syntax to semantics. Unknown objectives, missing macro arguments, malformed NBT paths, wrong argument counts.

02

Version-aware. A 26.3 command is flagged before it reaches a 1.21 world. Legacy folders are migration issues, not mystery load failures.

03

Portable output. Copy diagnostics as LSP JSON, or read the rule code and jump to the same span in your editor.

Built with respect for the tools before us

Rule semantics are modelled on Spyglass (MIT) and mclint (ISC). Both licenses permit commercial use with attribution. No GPL or AGPL linter code is bundled.
